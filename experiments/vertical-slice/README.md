## Calibration

`node scripts/generate-calibration.mjs` projects all 12 static floor rectangles through
Three.js PerspectiveCamera with the SAME default pose and Euler convention as cam-01.
World scale is 20 metres per plan unit; ground polygon height is .025 m. No World,
vehicle, current occupancy or evaluation module is imported by the generator.

Canonical pose: position [10,10.5,25.5], yaw 0°, pitch -33°, roll 0°, FOV 52°,
1280×720, aspect 16:9. Version: `cam-01-fixed-v1`. All 12 polygons are observable.
`packages/shared/calibration/cam-01.json` records pose/projection/polygons;
`facility.json` supplies the existing canonical FacilityConfig schema.

The generated outlines were visually checked against a real captured JPEG: both rows
follow the painted bay boundaries and labels A1–A6/B1–B6 match the static layout.
Debug copies are generated by overlay.py and the simulator diagnostics SVG. Neither
is written into cam-01's source canvas or uploaded for inference.

The calibrated API validates facility/polygon agreement at startup, rejects invalid
polygons, requires an authenticated session calibration binding, and checks JPEG
resolution. Simulator mount controls are locked when calibrated inference is active;
a changed scene-link pose is refused before capture/upload. Missing polygons continue
to produce UNCERTAIN. A changed viewpoint is tested as a calibration rejection, NOT
scored as valid camera evidence. A new valid viewpoint needs separate reviewed calibration.

The handshake is a camera's configuration assertion, not visual proof against a
malicious camera sender. The unchanged five-field FrameMetadata cannot authenticate
pose from pixels; do not claim general automatic camera-motion detection.

## Readiness, timeout and diagnostics

`/api/v1/health` distinguishes process liveness from inference state.
`/api/v1/perception/status` (ingest-token protected) reports weights/artifact availability,
model loaded, warm-up success, ready/degraded/unavailable phase, cold warm-up duration,
last frame identity/time, timings, actual detections, uncertain count, model provenance,
calibration and API process peak RSS. Warm-up executes the real model in a background
thread. Missing artifacts expose unavailable readiness; there is no fake detector output.

API inference timeout remains 10 s; upload timeout is 15 s. Timed-out worker output is
discarded. New calls are rejected while that worker finishes instead of queuing more
work. Tests verify the late result never changes occupancy and retry/new frames recover.
A native hung PyTorch call cannot be killed safely by an asyncio timeout; process restart
is still the recovery mechanism for an indefinitely hung worker.

## Evidence-based A2 plan (not implemented)

1. Preserve this baseline and split generated scenes by seed, vehicle identity/style,
   lighting and layout; keep a held-out set. Do not randomly split adjacent frames.
2. Investigate the appearance gap: current models are simple geometric cars with
   sparse wheel/window/detail cues; compare source-domain photographs and rendered
   vehicles at matched scale. The crop probe suggests scale alone is insufficient.
3. Train/fine-tune a suitable NVIDIA-supported detector on separately generated
   simulator annotations, with held-out daylight/night/occlusion evaluation. Never
   expose current-frame annotations to runtime inference.
4. Evaluate box-to-ground-plane mapping independently: perspective and large boxes
   can touch adjacent spaces; actual detections must establish the next mapping test.
5. Keep OPEN disabled until held-out empty/occupied/occluded cases support a defensible
   false-OPEN criterion. Zero false-OPEN with zero OPEN predictions is not evidence of
   useful availability recognition.
