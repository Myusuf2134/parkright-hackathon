# Meridian Maps

The student app's real map, routing and guidance (`apps/web/src/driver/maps`).

## Run it

```bash
npm run demo:student                   # http://127.0.0.1:5180/app/ on this computer
npm run demo:student -- --lan          # a phone on the same Wi-Fi, over HTTPS, with location
```

Browsers only share location over HTTPS or on localhost, so `--lan` uses HTTPS by default (`--http` turns that
off). It makes a throwaway self-signed certificate under `node_modules/`, and the phone warns about it once.
Over plain HTTP the app works from a chosen start point, says why guidance can't start, and keeps Start disabled.

### A certificate your iPhone trusts

The self-signed default shows a warning, and Safari may withhold location from a page it doesn't trust. For a
trusted connection, make a local CA with [mkcert](https://github.com/FiloSottile/mkcert) (Mac IP shown as `192.168.1.4`):

```bash
brew install mkcert
mkcert -install
mkdir -p ~/.meridian-certs && cd ~/.meridian-certs
mkcert -cert-file meridian.pem -key-file meridian-key.pem 192.168.1.4 localhost 127.0.0.1
open "$(mkcert -CAROOT)"   # AirDrop rootCA.pem to the iPhone (never share rootCA-key.pem)
```

On the iPhone: Settings > General > VPN & Device Management > install the profile, then Settings > General >
About > Certificate Trust Settings > turn on full trust for the mkcert root. Then:

```bash
npm run demo:student -- --lan --cert ~/.meridian-certs/meridian.pem --key ~/.meridian-certs/meridian-key.pem
```

If the Mac's IP changes, make a new certificate for it. Remove the profile from the iPhone when you're done.

To test movement on a computer: Chrome DevTools > More tools > Sensors > Location.

## Services and keys

| Need | Default, no key | Upgrade |
| --- | --- | --- |
| Basemap | OpenFreeMap | Any MapLibre style: `VITE_MAP_STYLE_LIGHT`, `VITE_MAP_STYLE_DARK` |
| Directions | OSRM on routing.openstreetmap.de, best effort, no traffic | Your own OSRM: `VITE_OSRM_BASE` |
| Live traffic | Not available, and the app says so | Mapbox Directions: `VITE_MAPBOX_TOKEN` |

`VITE_` values are visible to the browser. Use only a public `pk.` Mapbox token restricted to your URLs, in
`apps/web/.env.local` (gitignored). Check Mapbox's Product Terms on showing its routes over a non-Mapbox
basemap before shipping that combination. The Mapbox adapter has only been tested against mocked responses.

## Data

`maps/campus/osu.json` is generated by `scripts/campus/build_osu.py` from OpenStreetMap; each record names its
OSM object. It is community data, not surveyed on site. `kind: inbound` means a one-way driveway flows into the
entrance node. `kind: mapped` means an entrance is mapped but its traffic direction is unknown. Nodes that
driveways only flow out of are exits and are left out. `pedestrianDoors` are `entrance=*` nodes on the footprint
with a walkable way attached; a building's `doors` are `entrance=*` nodes on its outline.

## Choosing doors (`maps/nav/plan.ts`)

Each usable entrance is routed to, and the one with the lowest real time wins, counting the walk across any gap
the provider leaves at the end. The walk does the same from the two pedestrian doors nearest the destination to
the building's nearest door. Every fallback is stated in the route panel: a vehicle entrance used as the walking
start, a building centre used as the end, and the distance when a route stops short of its target.

## Starting guidance (`maps/nav/startGate.ts`)

Start needs a route, your own location as the start, a fix under 30 s old, and accuracy of 100 m or better. Each
failed condition has its own message and, where possible, a one-tap fix.

## Shared server limits

The default OSRM servers cut this machine off for minutes at a time after bursts of requests. `routing/polite.ts`
sends at most three at once, 250 ms apart, caches answers for five minutes and retries once, but real use needs
self-hosted OSRM or a paid provider. When cut off, the app shows "Can't reach the directions service".

## Adding things

- A campus: a data file and an entry in `maps/campus/index.ts`.
- A directions provider: implement `DirectionsProvider` (`maps/routing/types.ts`) and choose it in `createProvider`.
- A parking source: it reaches the map through `lib/directory.ts`, which ties a source to a campus garage. A
  campus garage with no source is listed as having no data.

## Honesty rules the code keeps

- Durations, geometry and instructions come only from the provider. Only a provider's traffic-aware duration is
  labelled as traffic.
- Progress moves only on real GPS fixes. Weak fixes never advance progress or trigger a reroute.
- A failed reroute keeps the current route and says so.
- Simulated and demo counts are marked on the pin, the route and the guidance screen.

## Tests

```bash
npm test -w @parkright/web
cd apps/web && npx playwright test                                   # no external traffic, recorded routes
cd apps/web && npx playwright test -c playwright.maps-real.config.ts # live services, deliberately slow
```

## Browser limits

Guidance needs the app open and on screen. There's no background tracking, lock-screen guidance or CarPlay, and
no voice prompts yet. Wake Lock keeps the screen on where supported.

Recorded-route tests prove the app's logic, not that live routing works; only the second Playwright command
exercises the live services. Browser tests emulate geolocation and bypass certificate checks, so neither iPhone
GPS nor iPhone certificate trust is covered by any automated test.
